Why Isaac Sim's window does not open in a platform desktop session (2026-10-23)
=============================================================================

Isaac Sim started from a platform desktop session crashes about 25 seconds in and never
shows a window. The same command opens the window in a KasmVNC desktop on the same node.

Cause: the session's X server, TigerVNC's Xvnc from /opt/pw/software/verified/tigervnc,
is built without the GLX extension. NVIDIA's driver needs GLX to show a window, and
without it the driver crashes instead of failing cleanly. Isaac Sim's log shows
'extension "GLX" missing on display ":1"' and then a segfault (exit code 139).

Not the cause: Isaac Sim runs on the same desktop with --no-window. KasmVNC's Xvnc, which
has GLX, shows the window at about 27 frames a second with the same node, image and
driver. Client-side changes (a newer Xlib, hiding the DRI3 library) made no difference.

Fix: build the session's Xvnc with GLX (TigerVNC supports it; it needs Mesa's libglx).
Nothing changes in Isaac Sim, the image or the launcher script.

Tested on awsgpu: NVIDIA L4, driver 610.43.02, Isaac Sim 6.2.0.1 (Kit 110.4), TigerVNC
1.14.1. "+extension GLX" does nothing because no libglx is installed. The crash is a call
to address 0 in libnvidia-eglcore.so from libcarb.graphics-vulkan.plugin.so.
